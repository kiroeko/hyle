## Coverage 负空间与裁决

- 4 个未观察 product file 分别是内部且不安装的 Sched↔IO integration bridge、只含声明的 timer 头、
  fcontext ABI 声明和 bulk 私有 access bridge；它们不是四项未实现公开能力；
- 唯二完全零命中的可执行产品函数是 `Scheduler::attach_io_` / `detach_io_`。直接调用私有桥会把测试绑死
  在实现细节上；Q07 必须通过 `IoContext` 公共组合证明单 owner、poll/wake、detach 和 teardown；
- 其余 zero-hit 为等价模板实例、当前调度交错没有选择的 queue/steal fallback、fault instrumentation 路线、
  defensive invariant，或 `CaptureWaker::await_ready()==true` 使标准保证不会调用的 `await_suspend`。它们均已
  回映到同一语义族，没有用重复测试追逐百分比；
- `DEFECT=0`：本波没有复现 correctness/security/UB/lifetime/concurrency 产品缺陷，Sched 不满足 reopen
  trigger，`module-status.json` 保持不变；
- 明确保留 `UNPROVEN(Q09)`：当前 ASan/UBSan、并发共享状态的 TSan、macOS backend，以及当前
  source/relocated static/relocated shared 最小交付矩阵。Windows Release shared/WERROR 已通过，但不能替代
  这些尚未运行的风险项。

因此 Q06 可以结束；下一波只审计 IO/Process factor，并用其公共 API 闭合两个 integration function，
不重新运行 Sched 性能 P1，也不因 coverage 数字重开产品。

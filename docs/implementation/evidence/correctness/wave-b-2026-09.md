## Coverage 负空间与 Wave 裁决

- shipping 未观察的 12 个文件全部属于 façade/declaration/visibility/private include，而不是完整运行时
  state machine；有 executable zero-hit 的主要源文件均已按上表回到平台分支、rare OS failure、等价
  template、已剥离 fault seam 或明确 owner 边界解释；
- `DEFECT=0`。本波没有复现 correctness/security/UB/lifetime/concurrency 产品缺陷，七个模块都不满足
  reopen trigger，`module-status.json` 保持不变；
- 明确 `UNPROVEN` 不被涂成 PASS：当前 build/package 的 source/static/shared，Windows/macOS/ARM/
  多 NUMA backend、适用 sanitizer/TSan，rare entropy/权限 failure、large-page partial reserve 和第 N 次
  partial-unmap system failure。前三类归统一 Q09；后两类是不可安全稳定制造的低频 OS 分支，保留机制
  proof 与诚实限制；
- 初次 fault timeout 证明大型 executable 不能被当作一个可控的测试原子。focused replay 已证明本波
  fault seam，但 Q09 必须按风险过滤/分片，不提高 timeout 或重复全模块；
- Q04 可以结束。下一波只审计 Wave C，不重跑本波性能 P1，也不追求 100% 行/分支覆盖。

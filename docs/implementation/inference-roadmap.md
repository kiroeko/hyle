# 推理工程范围与顺序

本页是**整体重点：做什么、做到哪里**。任务、负责人及进度只在[看板](../developer/inference-progress.md)维护；结构与合同见[整体架构](../architecture/inference-design.md)，已测性能见[decode结果](../developer/performance/decode.md)。

当前以底层推理支持为主。真实Qwen入口是验证消费者；基础库继续独立构建、安装与使用。当前没有自动goal，文档整理不恢复推理开发。

## 当前 goal 范围：全部 review 应对

以下保留完整开发范围，不能因某个子任务、模型组件或可选配置完成而缩小。长期取舍遵循[两项核心期许](../architecture/inference-principles.md)，具体方案仍须有真实模型、HYLE机制及成熟源码依据。

1. **完成底层功能与跨模型模块化架构。** 继续处理全部review中的普通／MTP、多会话、多请求／多任务、缓存、执行、工程和测量问题；补齐当前硬件可实现、可检查的相关底层能力。结合不同模型需求及SGLang、llama.cpp、vLLM、TensorRT-LLM、DeepInfer等成熟引擎的实际源码，形成模型无关且职责明确的模块、形状和状态合同，减少跨模块修改扩散与新增模型的重复开发。2B Qwen只是当前完整验证消费者，不能定义共同形状或完成边界。
2. **以冷期准备消化架构复杂度，保持推理性能。** 对每个受支持模型，都尽量达到专门为它准备的引擎的执行效率，尽量不因架构降低性能；保留其合法融合、布局、状态更新与执行快路径，不为统一接口增加不需要的阶段、搬运、同步或计算。复用Compute／Graph原执行、资源、Invocation和退休机制；清楚分开冷计划／加载／构图、热执行、请求政策、模型数学和完整状态发布。尽量在推理前确定实际程序、形状族、端口、资源布局与合法能力，热路径静态直接消费准备事实，不因新抽象增加运行成本。具体方案核实际模型需求、成熟源码与适用条件，以相应完整消费者验证，不能从Qwen单例推断所有模型。保留Snapshot、RNG、有序提交、背压、首错、权限和真实退休；继续覆盖会话换出换入、CPU/GPU overlap、设备token接力、稳定索引GDN／conv状态及SDK／Provider／CPU路由／依赖边界。
3. **让默认构建和正常默认用法获得有竞争力的性能。** 纯GPU decode是首要指标，查明并改善普通及默认完整词表MTP与llama.cpp的差距，复用Hyle既有加速并寻找通用优化；CUDA重点参考TensorRT-LLM。调研开关和候选最终收敛为适用时自动选择的快路径及必要回落，不让用户靠专用参数挑选实现。显式32K等特定配置只算实验／可选结果，不代签通用默认目标；显存避免以接近翻倍占用换速度，小幅差异结合实际收益权衡。
4. **以完整消费者与真实证据交付。** 架构调整做相关正确性和明显退化检查，性能改动用当前普通／MTP、单轮／多轮及相关批次完整对照，保留prefill、decode、启动、综合速度、内存／显存、实际版本、输出／算量差异与测量波动。补当前能做的组件与组合，不以完整大模型受限排除能力，也不把有限组件通过扩大为任意模型／拓扑证明；底座成熟后再用更强设备扩大整模型验证。

## 按两项核心期许调整当前工作

依次完成：共同执行架构 → 普通连续流水 → 默认普通／MTP性能 → 完整性能与兼容交付。工程与独立产品入口的已列整改已完成；不重开已完成MTP／多模态功能穷尽。

共同层拥有可共用的推进、权限与资源机制；模型保留数学、完整状态、合法融合和发布差异。已完成步骤驱动不等于全部架构完成，单个Qwen形状也不能定义共同合同。优先复用原Compute／Graph，不新增第二执行器、owner或退休账簿。

具体剩余任务、前置依赖、完成条件和百分比只看[顺序看板](../developer/inference-progress.md)，本页不重复同步。

## 当前实现概况

| 范围 | 当前结论 | 适用边界 |
|---|---|---|
| 功能与工程入口 | 已列请求／缓存／状态／取消／背压及CMake／初始化／独立SDK问题已实现并有限检查 | 限实际制品、配置和消费者，不代表任意组合均通过 |
| 共同执行架构 | 共同步骤、IO／槽、模型冷工厂与实际退休已接通；跨turn增量的交付状态见看板 | 当前还差原生FIFO逐出／重建及warm费用检查；不会用第二完整模型或未来跑分永久占住尾项 |
| 普通连续流水 | 已有跨pump、固定拓扑、首组小输入合并；剩余输入／读回及配置接线继续 | 相关改变随实现检查数值、寿命与明显退化 |
| 默认性能 | 有完整普通／MTP基线，仍有decode差距 | 默认完整词表；显式32K和局部kernel收益均不能代替默认整引擎结果 |
| 完整模型与产品 | Qwen有完整文本入口；GLM／Kimi／DeepSeek有组件结果 | 通用loader、C++ tokenizer、server／应用API、图片产品链路与多卡／多机未交付 |

制品身份、模型需求和实际支持范围分别记录，见[模型与算子地图](model-operators.md)及[引擎用法](../user/inference.md)。

## 当前 MTP 功能范围

上一轮约定的本机功能范围已完成有限复审：采样／接受与拒绝修复、有界多草稿、EOS／额度／context尾部、完整状态与RNG、会话恢复、量化及CPU／GPU混合代表路径。相关功能不重开穷尽；性能差距及所需执行调整继续。

Qwen有完整模型短旅程；GLM／DeepSeek／Kimi等组件仍保留上游激活、初始历史、角色与硬件边界。一个组件、多草稿共享规则或固定制品通过，不等于整模型、任意任务质量或全部后端已验证。

## 本轮可用范围

以Windows产品源码和已有2B输入／构建缓存为准；Apple仅使用指定MacBook Air。容量不足的整模型如实标记，但继续补本机可实现、可检查的数学／状态／量化／请求组件。设备、缓存和下载的精确约定只维护在[AGENTS.md](../../AGENTS.md)。

通用loader、tokenizer和server不是当前底座前置；运行中接纳、取消、背压、合批属于本轮底层能力。多卡／多机当前只审查设计边界，实际分片、通信和跨端点执行仍属后续产品路线。

## 架构和性能的实施边界

每个受支持模型尽量达到专用引擎效率；冷期确定程序、形状、资源布局和合法能力，热期保留必要动态身份／权限及真实退休，不为统一接口增加无效工作。具体职责只在[整体架构](../architecture/inference-design.md)说明。

实现附相关正确性与明显退化检查；性能用最终完整消费者比较启动、prefill、decode、综合速度和内存，保留实际算量、输出差异、参考版本及波动。当前结果与测法只在[性能资料](../developer/performance/decode.md)维护。

# SIMD 对拍全量换向统计（2026-07-13 复跑，含 Masked 族 vpand 修复）

> 每个 op × 每平台 × 每序的输赢一目了然。benchmark 本身内建 order-swap（env `HYLE_BENCH_HWYFIRST`）：
> 每 op 在"HYLE 先跑"(hf)和"Highway 先跑"(hwf)两序各测。列 **win=MSVC(Windows AVX2)、
> wsl=GCC AVX2、mac=NEON**；每列两子列 = 两序的 HYLE/Highway op/s 比值（>1=HYLE 快）+ 标签
> **W**(赢>2%)/**L**(输>2%)/**=**(平±2%)/**·**(该平台无此 op)。N=6 中位。

## 判定口径（真输的定义）
- **某平台"两序都 L" = 该平台真输**：换向后 HYLE 仍慢，排除了"第一槽冷启动"harness 伪影。
- **x86(avx2/sse4) 与 NEON 是各自独立的后端实现**，一个 op 完全可能"x86 真输、NEON 赢"（反之亦然）。
  因此**真输按平台判**——x86 上的真输不因它在 NEON 上赢而免责，反过来也一样。
- 不存在"必须三平台全慢才算真输"的门槛；只要**任一平台两序都慢**就是那个平台需修的真输。

## 权威统计（当前代码，含 IfThenElseZero blendv→vpand 修复 f32b7ba）
- 总 benched op = **266**
- **真输 op 数（至少一个平台两序都慢）= 50**（Masked 族修复前为 64）
  - **win (MSVC AVX2) = 36**（前 48）   |   **wsl (GCC AVX2) = 15**（前 23）   |   **mac (NEON) = 4**（前 5）
  - 三平台同时真输 = **0**（NEON 独立实现，x86 输的项在 NEON 上大多 W）
- 其余：平/赢 = 114，HYLE 全序赢 = 14，混合(仅单序慢/布局伪影) = 88
- **Masked 族一次修复清掉 14 个真输**：IfThenElseZero/IfThenZeroElse 从 blendv/vbsl 改
  vpand/vandps/vandq（照 Highway，掩码 raw 本就是全 1/全 0 lane 图样，无需 2 周期 blendv）。

> ⚠️ 两点必读：
> (1) 此 harness 是**内存-bound**(Load+op+Store)。个别"真输"项在 compute-bound 链式或 realistic
>     4-累加器 streaming kernel 下会翻正(如 128-cmp 族 Max128 已 compute-bound 1.04×、HighestSetBitIndex
>     compute-bound 1.17×)。按用户口径 **realistic kernel 换向仍输才是真输**；本表是内存-bound harness
>     下的"真输上界",逐项修时需再跑 realistic kernel 复核。
> (2) MSVC 真输数(36)高于 GCC(15)：MSVC 对 store+reload/标量展开 codegen 优化弱于 GCC,第一槽惩罚更强。
>     **同一 VS2026 编译, Highway 快 = HYLE 源码写法问题,非 VC++ 版本问题。**

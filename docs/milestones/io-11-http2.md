## 为什么是它（以及为什么先不做）
HTTP/2 的多路复用 + HPACK 头压缩 + 流控是高并发 API 服务的下一档能力。但它建在一个**稳定的 HTTP/1.1 连接管理层**之上才有意义——io-10 的三层分工（借 parser + 自写集成层 + 薄模型）刚定案并修完一批跨平台 bug，先让它在生产站稳，再往上叠 H2。这是 JIT 生长原则：后期里程碑依赖前面实现学到的东西，提前写 = 空想。

## 计划方向（待开工时定形）
- **借 nghttp2 的 parser/HPACK 部分**（同 io-10 借 picohttpparser 的「借纯协议、自写集成」策略），frame 层 / 流状态机 / 流控接 io-10 的连接管理与 co_await TcpStream。
- **WebSocket 同期可评**（帧协议，借或自写）。
- **gRPC 更靠 L1**（依赖 protobuf 编译器，不在本模块）。

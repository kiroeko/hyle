# HYLE 里程碑索引

> 实现的真正"步骤"在这里——约 58 个里程碑，每个 1-4k 行、可独立编/测/基准。`roadmap.md` 是依赖层(阶段)的拓扑序与决策；本目录是**可执行的逐步计划**，每步一文档。
>
> **粒度原则**：一个里程碑 = 一次"写完→编过→单测(覆盖达 Tier 标准)→基准→提交"的闭环。
>
> **生长方式（JIT）**：最先执行的 `00-scaffolding` 与 walking-skeleton 几步已写完整；其余**临到该模块开工前再补全细节**——后期里程碑依赖前面实现学到的东西，提前写=空想。索引行先占位（ID/依赖/目的/LOC），细节随推进生长。
>
> **clay 能力查漏参考**：见 [`../architecture/clay-coverage-map.md`](../architecture/clay-coverage-map.md)——clay 每个文件 → HYLE 对应物/状态/LOC 的逐文件映射。目标是 **能力覆盖 clay + 性能 ≥ clay,接口不必一致**(clay 用户大多已不在,无接口兼容需求;HYLE 怎么好用/怎么 SOTA 怎么来)。**每个吸纳 clay 的里程碑闭环前对照 clay 同名文件查漏——看有没有漏掉仍需要的能力**,缺的补(或显式登记不做),不许默默略过(红队核账 2026-06 立此纪律)。**注意是"能力查漏",不是追平 clay 的 API 签名/命名。**

## Walking Skeleton（最先做，纵切验脊）

打通"**一个 fiber 跑起→让出→被唤醒**"。= `00` + 各模块**第一个最小里程碑**串起来，**先不做 work-stealing/多后端**。验掉最高风险的 fcontext+调度脊，之后逐里程碑加厚。

骨架路径：`00-scaffolding` → `error-01` → `platform-01` → `mem-01` → `container-01` → `sched-01`(单 worker 单队列)。

## 预测 vs 真实 LOC（防玩具化）

### 整体进度(诚实,2026-07-02 实测)—— 三个分母别混

> **实测代码 11,551 行**(生产,cloc `include`+`src` 的 header+C++,不含 CMake/测试/文档/vendored;上次 2026-06-30 为 8,543,本会话 time-02 时间轮+CommonTimeoutQueue / sched-04b fiber sleep / sched-04c 定时 CV / io-01 proactor + io-02/03/04 全后端真 IO op + io-04 co_await 层(net/io_context)+ shard-per-core(fiber 亲和 spawn_on + per-worker ring)+ TcpListener/Stream + UdpSocket 封装 + pipelined P0 hang 修复 + park 合并 + io-07a/b multishot accept/recv + provided buffer ring 增约 3.0k)。三个"进度"说法分母不同,**混用会得出误导数字**:
>
> | 口径 | 分母 | 当前 | 说明 |
> |---|---|---|---|
> | **clay 吸纳权重** | 被重构的旧 clay 库 | ~33%(coverage-map) | 基础层已基本吸纳 + time 双定时器(net-new);**分母是旧库,不是新愿景** |
> | **自有生产 LOC 比** | 投影完成时 ~28-40k 自有(2026-07-03 审计+HTTP 定案后上修) | **~29-41%** | 11.42k/(28-40k);但 LOC≠完成度(广度缺口不体现在比值里) |
> | **对完整愿景的功能完成度** | 完整 HYLE 自有(全广度 + io/compute/graph,**不含借入的 ggml**) | **≈33%**(band 28-40%) | 见下方"审计上修"算式;io net(tcp+udp)已落地,HTTP/file/shmem 待 |
>
> **"≈33%" 怎么算出来的(2026-07-03 现值;历史推导见下方"第二轮下修"+"审计上修")**:
> - **法一 · LOC 比**:11.42k(已写生产,cloc 实测)÷ ~34k(审计+HTTP 定案后中值,band 28-40k)= **≈33%**。
> - **分母为何从 26k 涨到 34k**:参考库审计补登了之前漏算的真实广度——sched 并发原语/JoinHandle/阻塞卸载 + io 超时/multishot/TLS/DNS/**HTTP serving+client** + obs 埋点。HTTP 尤其大(推理引擎北极星必需 REST)。**不是退步,是把该算的补进分母**。
> - **为何不是更低的"个位%"**:那个数把**借入的 ggml ~100k 当成 HYLE 要写的**塞进分母。但 ggml 是 compute 支柱**借核不造**(scope 明列),不计入 HYLE 自有完成度——剔除后回到 ≈33%。
>
> **33% 但"最难的一半未动工"(关键定性)**:**compute / graph 两大支柱 = 0 行**;**io 支柱**:proactor 三后端 + read/write/socket 真 op + tcp+udp net 上层(co_await + shard-per-core + benchmark + park 合并)全落地(无 stub,双平台真测),但 **超时/TLS/DNS/HTTP serving/file/shmem 未做**(HTTP 是推理引擎刚需)。它们仍占**剩余自有工作量的大头**,还是"异构混合极致性能 + AI serving"的卖点本体。已写的 ≈33% 是**地基 + sched 全支线 + io(proactor + tcp/udp net + shard-per-core)+ simd f32 核**,质量高、SOTA 对标、双平台+WSL TSan 验证(非 stub);但**广度薄**(simd 仅 f32 9 op,无 i8/i16 量化;AVX512/NEON 未硬件实跑)、**compute/graph 未开工、io 缺 HTTP/超时/TLS/file**。故:**按代码量 ≈33%,但按"差异化能力"更保守——剩余工作含全部头牌支柱主体 + 北极星必需的 HTTP serving。**

> **真实LOC = 该里程碑自写代码的 cloc 实测（生产+测试，不含文档、不含 vendored 第三方）。**每步闭环后回填。
> **预测/真实差距是"防玩具"信号**：差距大必须在该里程碑文档解释清楚——是"骨架版刻意精瘦、重活在后续里程碑"（合理），还是"偷懒 stub/空实现"（不可接受）。
> 已完成几步真实普遍 < 预测，因走的是 **walking skeleton 路径**（每步只做最小纵切，模块重头留加厚里程碑）；非玩具的证据是每步的真测 + TSan + 对抗式自审，详见各文档。

### 系统性 ~10x 高估的根因(2026-06-28 用户提出,数据调研)

观察:已完成里程碑真实 LOC 普遍是预测的 **1/5 ~ 1/20**(util/math 类小件最甚 ~10-18x)。**调研结论:主因是预测方法,非玩具**——三条证据:

1. **预测锚错基准**:roadmap "每里程碑 1-4k 行" 是按 **clay C++17 体量**估的。clay 满是 SFINAE/手写 Result/per-type allocator/C++17 polyfill;HYLE C++23 合法地更精简——`<bit>`/`<numbers>`/`std::expected`/concepts/`std::pmr` 把 clay 几百行样板**直接吃掉**(功能在 std 里,非没实现)。math-01 铁证:clay 458→28 行。
2. **倍率 ∝ 可压缩性**:gap 最大的恰是样板最密的 util/math(std 吃得最多);gap 最小的是 error/platform/SwissTable 等**不可约**真逻辑(~3-7x)。**反向证明非均匀偷工**——若玩具,大件会同样缩水。
3. **完整性标尺 = 能力覆盖(对照 coverage-map 查漏),非 LOC、非 API 签名**。每里程碑闭环对照 clay 同名文件查有没有漏掉仍需要的**能力**,缺的补或显式登记(container-04b/06b 即可见的登记延期)。**"吸纳 ≠ 追平 LOC,也 ≠ 追平接口"**——接口怎么好用/怎么 SOTA 怎么来。

**校准规则(此后预测按"可约性"分档,非一律 clay 体量):**
- **std 现代化重的小件**(util/math/纯类型设施):预测 **0.03-0.2k**(真实多 30-200 行)。
- **真算法/容器/平台原语**(hashmap/pool/parker/clock):预测 **0.1-0.5k**。
- **不可约大件**(path/fs 字符串处理、SIMD kernel、sched asm/调度、io 后端、compute):预测**接近 clay 体量**(path clay 1372 行→HYLE 估 0.6-1k;simd/sched/io/compute 仍 2-10k 级)。**这些若也缩成 1/10 才是真玩具信号,届时必须补实现而非改预测。**

### 完成时总量再投影 + "高估 vs 玩具"双向校准(2026-06-29,simd 支柱做完后)

> simd 支柱 6 里程碑做完 = **实测 ~2.3k 生产**(旧表预测 10-16k)。用户质疑:"确定高估,不是玩具?" 实测核验后的诚实拆解(两半,别只甩一边):
>
> 1. **不是玩具(铁证)**:simd 后端每个 **33 个真 op**(真 intrinsic)、**零 stub/TODO**、vec/dtype 测试断言 43/41 条 + 全 65536 fp16 模式硬件逐位对拍 + dot/saxpy 实测追平 Highway + 红队揪出真 ODR/SIGILL bug。玩具撑不住这些。
> 2. **但"5-7x 纯高估"是误导**:simd 2.3k vs Highway 100k **非功能对等**——HYLE 现做 **4 lane 类型 + ~25 op + 2 ISA 实测**;Highway 是 **12 类型 + ~200 op(swizzle/gather/scatter/compress/table-lookup,HYLE 全无)+ 6+ ISA**。dot/saxpy 追平只证"**已做的 op 上**追平"。i8/u8/i16/u16/i64/u64 量化类型等是**登记延期的广度**,补齐后 simd 涨到 **~5-8k**(非停在 2.3k)。
>
> **故 simd 真实高估约 2x(非 6x)**;foundation 的 5-6x 高估是真(std 取代)。校准规则 #3 对 simd "2-10k 级"基本对,只是要明确**2.3k 是"核心数值子集做好",非"全广度做完"**。
>
> **完成时总量(实测密度再投影,含广度补全)**:HYLE 自有 **~22-30k 生产 / ~40-55k 含测试**(中值 ~26k 生产);第三方 vendored ~150-250k+(ggml 100k+ 主导);项目总足迹 ~200-300k+。详见 [`../architecture/hyle-scope.md` 规模节](../architecture/hyle-scope.md)。

### 完成时总量第二轮下修(2026-07-02,io 破土后,分锚外推)

> 上一版投影 30-45k(2026-06-29 simd 后)仍偏高。用**已完成模块的实测密度**分锚外推剩余(非用虚高的"1-4k/里程碑"),投影收窄下移到 **~22-30k**:
>
> **实测锚**(已完成,可信):平台原语簇(platform 5 件)=1318 行 / 大容器簇(container)=2488 / sched 全支线(fiber+调度+同步+定时)=1055 / io 支柱(proactor 三后端 + net co_await + io_context + tcp + udp + shard-per-core)=1550。
>
> **按锚外推剩余**(置信度递减):simd 广度(+2-3k,有 f32 核密度锚,中)/ sched 后段协程·取消·关闭(+1-1.5k,中)/ **io file·shmem(+1-2k,中——tcp+udp net 已落地=1.55k 实测锚)** / **compute 借 ggml 薄层(+3-5k,很低——0 行无锚)** / **graph(+2-3k,很低)** / close C-ABI·FFI·serialize(+2-3k,低)。
>
> **→ 新投影 ≈22-30k 生产,中值 26k**;完成度 **11.28k ÷ 26k ≈ 43%**(band 22k→51% / 30k→38%)。**⚠️ 此值已被下方"审计上修"取代(现值 33%/34k),本行保留为推导历史。**
>
> **三条诚实标注(别把 43% 当"快到一半")**:
> 1. **投影不确定性几乎全在两大支柱**(compute + graph)——0 行,外推置信度低;foundation+sched+simd+io 才是实测硬锚。若 compute/graph 比预想重(GPU 抽象、Vulkan kernel),分母会回涨。
> 2. **LOC 43% ≠ 能力 43%**:compute/graph=0 行且是"异构混合极致性能"卖点本体;按差异化能力,主观更保守(头牌未动)。
> 3. **这是第 3 轮修正**(76-120k → 30-45k → 22-30k),每轮下修都因"实测证明剩余也享 C++23 压缩"。**收敛趋势=早期系统性高估的证据**,但 compute/graph 未落地前不宜再激进下修——**22-30k 是当前最诚实区间,compute/graph 一落地就复核**。
>
> **⤴ 审计上修(2026-07-03,参考库对照 + HTTP 定案)**:上面的 22-30k 是审计**之前**的投影。审计补登了一批真缺口机制(sched-09/10/11 并发原语·JoinHandle·阻塞卸载 + io-06/07/08/09 超时·multishot·TLS·DNS + io-10/11 HTTP serving/client + obs-02 埋点),这些是"漏了没抄/北极星必需"的真实新增工作量,**分母回涨到 ~28-40k**(见 roadmap 合计行)。故完成度按新分母 **11.28k ÷ ~34k ≈ 33%**(band ~28-40%)——**不是退步,是把之前漏算的真实广度(尤其推理引擎必需的 HTTP serving)补进了分母**。这印证了标注 1:早期"下修"部分是因为剩余广度还没被完整列出来,补全后回涨符合预期。

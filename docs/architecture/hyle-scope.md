# HYLE 产品范围

HYLE 是 C++23 推理引擎项目，基础模块提供内存、数据结构、SIMD、调度、I/O、设备计算与 Graph，
可以脱离引擎独立构建、安装和使用。资源流送、数值管线和异步服务也可复用这些模块。
当前目标是 Windows、Linux、macOS 上的单机 CPU、CPU＋一张 GPU、单 GPU 推理，具体组合受系统和后端支持限制。
当前主阶段先收敛底层推理支持，以项目内引擎执行真实模型发现缺口；完整应用、server 和 API 随后推进。

## 为什么组合本身有价值

单项kernel快并不能消除重复分配、格式转换、线程池、同步和临时owner造成的整条链成本。
Hyle复用成熟机制，承担清楚的C++语义、资源寿命和交付；没有这种集成价值的包装只增加维护负担。
不同领域共同检验机制；模型与推理政策归项目内的引擎层，通用模块不依赖模型实现。

## 分层与组合

Core、Error、Platform 分别提供编译与布局原语、失败表达和 OS/硬件事实；Mem、Time、Obs、Util、
Container、SIMD、Math 提供可组合机制。Sched 与 IO 拥有任务、取消、唤醒、文件、网络和协议生命周期。
Compute 拥有设备、资源与算子执行；Graph 拥有逻辑 DAG、冷编译和执行计划。
`engine/` 在这些模块之上拥有模型接入、生成／接受策略、完整会话和请求编排。
新增模型组合已有数学与状态机制，新增后端集中在相应计算承载；底层不反向依赖引擎或模型名单。

依赖方向服务于这些职责，不为图表整齐建立空模块。内部 factor 用来隔离源码、类型或交付依赖，
普通消费者选择公开产品；声明和装配方式见[构建架构](build-system.md)。
底层不重复创建线程池、allocator、时钟、事件循环或错误模型；高层组合仍须承担完整的失败与关闭语义。

## 推理引擎需要什么

基础库需要支持长期运行的完整旅程，不能只提供构造或 benchmark 入口：

- 权重和状态具有明确的存放位置、格式、owner、预算、ready 与最后使用边界；有限 staging 可增量搬运资源。
- 可复用计算制品与每次执行的可变状态分开；并发槽、动态形状、分页/变长输入和原生重放有明确成本。
- CPU、GPU 和混合计算使用相符的数值、布局、状态与完成合同，GPU 失败不会暗中改在 CPU 重算。
- 取消、部分接纳、异步失败、关闭和旧结果保活仍保持正确；内存不足时可以解释资源归属。
- 普通用户不选择算子库或排列 Provider；库按真实请求和设备能力绑定实现，引擎决定精度、放置及资源政策。

模型文件解析、tokenizer、生成和接受策略、KV/prefix/expert 缓存政策、请求调度及 serving 由 Hyle 引擎层负责。
Compute／Graph 提供可复用的计算、存储、状态版本、依赖和完成机制。模型相关数值边界见
[Compute](compute-design.md#推理负载与数值边界)，原生后端和混合计算见[路线设计](compute-routes.md)。
当前 Qwen 完整文本路径及其它模型的有限 MTP 组件结果见[模型与算子覆盖](../implementation/model-operators.md)。
完整引擎是产品目标，不表示通用 loader、C++ tokenizer、服务入口或图片链路已经完成；
它们也不成为本阶段底层支持工作的前置。
当前可运行边界见[引擎指南](../user/inference.md)，实施顺序见[推理工程计划](../implementation/inference-roadmap.md)。

## 扩展边界

新公共机制应解决可重复出现的真实任务，有清楚的 owner，并能减少消费者的复制、同步、分配或维护负担。
成熟实现或已有原语能自然完成时优先复用；不能因参考库有一个 API 就增加相同菜单。

共享内存广播、通用 trie/SlotMap、动态插件管理、复杂 topology/pressure 和可变分段字节链等需求，
需先确认现有组合的具体不足，再决定是否需要公共抽象。这些例子不是待办表或新增功能承诺。
跨机器协同、分布式训练、自动微分和 HIP/ROCm 不属于当前范围。
引擎拥有推理服务的请求生命周期；账户、计费等部署方业务政策由上层应用决定。

## 完整性与成本

一个能力的价值包括正常使用、更新、失败、并发、取消和关闭；“有类型”不等于这些旅程已经可用。
比较实现时核对同一精度、输入/输出、owner、并发和最终完成边界，计入 packing、搬运、等待和回收。
先理解复杂度和资源成本，再测实际差异；测量方法见[性能开发说明](../developer/performance/README.md)。

平台、设备、ISA、dtype、布局与格式支持分别说明。编译、真机正确性和性能是不同结论；
一个后端或一个模型的结果不能代替其它组合。用法和已知限制只在[用户文档](../user/README.md)维护，
架构页解释取舍，不维护重复支持矩阵。

## C++ 交付与 ABI

引擎以 `hyle` 可执行程序交付；基础模块提供完整源码、headers＋static、headers＋shared 三种 C++ 交付，
不承诺跨编译器/STL 的 C++ ABI。
目前没有独立 C API 或外语绑定。内部 C、汇编及第三方入口不构成公开 FFI；只有真实跨语言消费者
需要完整的创建、调用、错误、取消、销毁和卸载合同后，才讨论稳定外语入口。
授权方式独立于交付形状，见[许可边界](licensing.md)。

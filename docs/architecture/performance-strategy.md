# 性能目标与比较边界

HYLE 追求合理的算法复杂度，减少真实任务中的分配、复制、同步和调度开销，并尽量复用优秀成熟实现。
性能结论必须限定能力、语义、输入、硬件、系统、工具链和源码版本，不能用全库平均分代替。

公平比较要求两侧完成同一件事：数据格式、精度、状态、输出寿命、完成等待和计时边界一致。
如果一方提前展开权重或缓存，准备时间与常驻内存要单列；不能把不同存储方案的结果直接解释为同工实现排名。

延迟、吞吐、内存、冷准备和尾部开销分别报告。计时分辨率、噪声、漂移和错误路径会使结果失效，
应先检查仪器和边界。排除这些因素后，小幅且稳定的输项也要如实记录并调查原因，不能因落在容忍带内而写成平局。

优化先查算法、复杂度、搬运、分配、同步、cache、向量化和线程；再根据证据运行有助于定位的实验。
不通过改变输入、精度或完成语义制造优势，不为微基准添加公共快路径。
成熟实现更好时优先采用它；同路径、同机器码的结果也应如实说明。

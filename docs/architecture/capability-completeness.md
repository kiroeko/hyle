# 基础库能力完整性

功能完整指正常用户任务有自然、可验证的完成路线；有一个 API 不等于完整。
只覆盖初始化或 benchmark、缺少正常关闭、失败恢复或互操作的功能仍有缺口。

需求来自真实消费者、语言和平台标准、成熟实现中的常见任务，以及现有公开承诺。
推理是当前主要消费者；渲染、资源流送、数值管线和异步服务也用于检查基础机制是否被某个模型过拟合。
参考库用于发现任务和成熟形状，不照搬全部 API。

## 设计时需要说明什么

- 用户如何创建、正常操作、组合、取消、关闭和销毁对象。
- 所有权、借用失效、线程安全、重入及进展保证。
- 空输入、边界、溢出、内存不足、系统和设备失败的行为。
- 时间和空间复杂度，以及分配、复制、同步、线程和系统调用成本。
- 支持的系统、数据类型、布局与源码、静态库、共享库交付限制。

根据实际问题检查相关部分，不要求每次修改重做全库审计或填写固定表格。

## 机制与策略

HYLE 提供可复用的机制。模型格式、tokenizer、采样、KV 缓存策略、请求政策和部署编排由引擎拥有。
但共享状态、资源寿命、异步搬运、取消后排空等通用问题，应有可靠的基础接口，避免每个消费者重写竞态处理。

能力可以由 HYLE 实现、成熟依赖承载、现有原语自然组合，或明确交给上层。
选择成熟实现时保留其完整算法和运行时边界，只增加有必要的错误、资源、异步或交付适配。
不复制已有内存、调度、错误、时钟和设备探测机制；不为短样例隐藏正常分配和同步成本。

## 如何验证

从公共接口运行真实消费者，检查正常路径、错误、寿命和相关并发，再按实际需要测量性能。
原子操作与原子比较，完整旅程与相同完成、持久化和销毁语义的旅程比较。
未支持、未验证和已知失败分别说明；不能用孤立 API 或旧实验推导整个产品可用。

# C++ 交付与 FFI 边界

当前产品只提供 C++23 源码、静态库和共享库，没有独立 C API 或 Java、.NET、Python、Rust 绑定。
共享库不自动产生稳定 C++ ABI，也不意味着需要外语接口。
早期 C schema、bridge 和 managed probe 已移除，不承担兼容承诺。

未来有明确外语消费者时，围绕实际任务设计窄接口，并说明拥有者、版本、错误、内存释放、
回调线程、取消、销毁和卸载。避免逐项复制全部 C++ API。

可能的边界使用固定宽度整数、明确对齐的 POD、指针＋长度、opaque handle 和函数指针＋context。
创建者负责销毁；不跨 allocator 释放，不暴露 STL、模板、引用、异常、虚表和编译器对象布局。
需要用目标语言验证实际 shared library 的正常、失败和并发生命周期。

内部 OS、汇编、GPU 和第三方互操作仍可使用私有 `extern "C"`；这不是公开 FFI。
安装产物应隐藏这些内部符号及第三方实现入口，显式导出的 C++ 符号仍遵守对应工具链 ABI。
不为假想绑定添加 CMake 选项、第二套对象模型或常态开销。

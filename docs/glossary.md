# 术语表

HYLE 的文档和性能记录里，常用一些缩写和固定说法。本页给出它们的含义，便于读懂各篇文档。
接口细节以公开头和对应指南为准。

## 工况与测量缩写

| 写法 | 含义 |
|---|---|
| `P154＋64`、`P256＋32` | 每轮 154（或 256）个 prompt token，生成 64（或 32）个 token |
| `C1024` | 每个会话的上下文容量为 1024 个 token（`--capacity`） |
| `N2`、`N4` | 驻留完整状态版本的预算为 2（或 4）（`--max-sessions`）；保留的前缀检查点也会占预算，不等于服务用户总数。执行候选另按 R／K 留出空间 |
| `R1`、`R2` | 一次执行最多合批 1 条（或 2 条）序列（`--active-sequences`） |
| `B2` | 两会话合批的普通推理基准，通常是 `N2／R2`、`C1024`、三轮固定输入回放 |
| `K1`、`K4` | MTP 每轮最多提出 1 个（或 4 个）草稿 token（`--mtp-max-drafts`） |
| 单轮／两轮 | 一个会话里只有一轮请求，或在同一会话上追加第二轮 |
| prefill／decode／综合 | prompt 处理吞吐、生成吞吐，以及包含两者的整段会话有效生成吞吐，定义见[性能测量](developer/performance/README.md#推理对比固定报告) |
| 固定输入回放 | 用预先确定的 token 序列驱动 decode，保证两边工作量相同；不是自然生成 |
| 交错进程 | 两个引擎的测速进程轮流启动，避免机器状态偏向一方；内存另用独立进程采样 |

## 推理引擎对象

| 术语 | 含义 |
|---|---|
| Model | 已加载的模型：权重、冷编译的图、执行端点和容量，被所有会话共享 |
| Session／会话 | 一个可以续算的完整模型状态，包括该模型所需的 KV、递归状态、位置、pending 和采样游标 |
| 请求／turn | 一次用户输入及其输出额度、停止条件；一个会话可以有多轮 |
| episode | 一次实际执行：选定的成员、输入、候选状态，以及对应的完成和提交 |
| pending | 已确定为输出、但还没写进模型状态的最后一个 token；下一步作为输入消费一次。输出确定和交付给用户是两个时刻 |
| ledger／提交账簿 | 记录已提交的输入和输出，保证每个输出只观察一次，恢复时按它重放 |
| Snapshot | 某个时刻的只读完整状态版本，可被前缀缓存和分叉共享 |
| 前缀缓存 | 按已消费的 token 序列索引完整检查点，新请求命中时跳过已算过的前缀 |
| 淘汰与恢复 | 空闲会话的设备状态被回收；下次用到时按 ledger 重算，或从主机内存中的完整镜像换回 |
| MTP | multi-token prediction：模型自带的草稿头一次提出若干 token，target 模型一次验证，接受合法前缀 |
| target／draft | 主模型与 MTP 草稿头 |
| catchup／lag | lag 是草稿状态落后主模型的行数；catchup 是补齐这些行的计算 |
| StateHead | Compute 的通用集合版本 head；按 expected-base 校验并发布一组状态，不解释模型布局 |
| 冷路径／热路径 | 冷路径负责加载、编译和重新规划等准备；热路径负责准备完成后的重复执行。新形状仍可能触发冷准备 |

## Compute 与 Graph

| 术语 | 含义 |
|---|---|
| Provider | 一种算子实现来源，如 ggml、cuBLAS、FlashInfer、oneDNN、MLX、HYLE 自有 kernel |
| region | Graph 中交给一个 Provider 整体执行的一组节点 |
| Executable／Invocation | 编译好的不可变图，以及它的一个执行槽；执行槽拥有绑定、workspace 和结果 |
| Completion | 一次提交的完成观察对象；成功等待与错误观察要区分，观察出错本身不能证明设备工作已经退休 |
| 退休（retire） | 设备工作真正结束；取消请求本身不等于退休。资源释放或复用还须满足旧读者、结果与租约的寿命和权限约束 |
| ReadLease／WriteLease | 分别表示存储的只读与独占写权限；保活、范围和最后使用共同约束何时可以释放或覆盖 |
| capture／replay | CUDA Graph 录制与重放；地址或拓扑变化可能要求更新或重新录制，是否可复用由真实图和原生接口决定 |
| Commands／PreferCapture | 直接逐条提交命令，或优先录制成原生图后重放 |

## 状态与范围措辞

| 说法 | 含义 |
|---|---|
| 组件检查 | 只用模型的部分层、原始权重片段或上游提供的中间输入验证数值，不是整模型运行 |
| 完整短流程 | 加载完整权重并跑完一次普通或 MTP 生成，只验证功能，不代表任务质量或性能 |
| 范围重叠 | 两组样本的最小值到最大值区间有交集，差异可能只是噪声，不能说稳定更快或更慢 |
| 采样峰 | 内存或显存按固定间隔采样得到的最大值，是真实峰值的下界 |

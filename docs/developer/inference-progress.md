## 本批结果与下一步

空闲入口现可按原 N×R 有界接纳预热新增普通／MTP-prefill 后缀；动态形状接纳计入该步并单列计时。普通已提交、无 draft 状态的多成员批次可丢弃取消成员，幸存者发布原候选并继续；结果用 disposition 区分，成员退休不再隐式中止幸存者。EOS 已集中到模型配置。最终只补编两个产品 TU 和一个检查 TU，复用缓存。微型 AA／E4 CPU greedy 检查通过：旧读者／fork、单成员取消、空账簿、保留原候选、继续推理、全部取消、预热复用和最终退休。首个用例因准备顺序错误失败，已仅修用例并保留记录；没有新 GPU 在途、随机取消、设备故障或完整速度结论。

下一步先提取真实共同请求编排与模型适配边界，补齐取消路径的有限设备检查；再实现持续工作态／按需快照及版本化状态槽。旧快照仍被缓存或分叉保留、原生失败未退休时，必须保活原槽或走合法 COW／扩槽回退。不能假设两份缓冲永远够用，也不把逻辑截断当作原生退休。完整主机会话镜像与形状政策随后补齐；重叠执行用于争取反超。

单 carrier 不是当前差距的已证实原因，实际参考也逐步同步。新的[同设置 CPU 诊断](../evidence/performance/inference-b2-peer-cpu-critical-2026-10-26.json)核对完整工作、198 ID 与 99 根；共同90稳态根的 GPU／CUDA API 外运行区间为99.701／14.365ms。差85.337ms支持减少主机协议工作，但不是全额可删成本。旧 node 诊断与新 graph 包络不混减；采样／端点／数值和状态合同的边界继续保留。

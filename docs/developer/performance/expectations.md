# 性能目标与取舍

HYLE 面向真实调用提供基础加速。优先保证正确性、精度、寿命、并发和资源限制，再改善复杂度、
分配、搬运、同步、吞吐和延迟。不能以弱化语义取得同工比较的胜利。

- 选择实际会被用户采用的成熟参考实现，`std` 不总是足够强的参照。
- 结论限定实现版本、输入、精度、调用方式、硬件、工具链与交付方式；两例赢不能推出整库领先。
- 速度、尾延迟、显存/内存、搬运和能耗分别报告，收益与退化同时保留。
- 可复现的小幅落后也是落后。先排除仪器分辨率、统计不确定性与工作量差异，再调查实现原因。
  5% 等实用容忍值不能把稳定的 1% 落后改名为持平。
- 微基准用于归因，实际消费者用于确认收益和接口是否自然。API、对象布局和常驻资源的修改要考虑
  整体效果，避免只对一个跑分形状有利。

比较方法见[公平比较与报告](benchmark-evidence-standard.md)。观察到的差异、调查优先级和产品取舍
分别说明；没有测清时写出不确定性，不推断成平局。

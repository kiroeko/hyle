# 测量与统计

直接构建相关 C++ benchmark，使用 `scripts/bench-stat.py` 或实验自己的分析脚本处理原始数据。
`scripts/hyle_perf/` 中保留的统计与日志解析函数可以复用；不需要治理 runner 或证书。
比较工作量与边界先看[公平比较](benchmark-evidence-standard.md)。

## 调用与样本

1. 使用实际 release 产物，记录版本、flags、backend 和输入。warm-up、冷准备与热调用分别处理。
2. 优先成对、交错执行双方，使相邻样本共享温度、频率和后台负载。交换 A/B 与 B/A 顺序；同一实现
   对自身执行相同路径与拓扑的 A/A，检查先后位置是否已有固定差异。
3. 保存所有样本。独立进程、独立 block 与进程内重复是不同层次；不能把相关的内层重复当成独立样本
   人为缩窄区间。明确哪个层次用于推断，单进程 block 区间只描述该次运行。
4. 按预先选择的方法分析 paired ratio 或 delta；通常报告中位数、区间、样本数和适用 tail。
   多顺序、分配位置、布局与规模先分别报告，再按说明的规则汇总。

样本数根据噪声与需要分辨的差异决定，没有固定的开发上限。发现计时边界、热状态或仪器错误时先修正，
不要靠追加样本掩盖偏差，也不要仅因为结果不好看就重复或挑选。

使用 nanobench 的同进程双路线时，`Bench::compare()` 会交错 alternatives；先完整 `run()` 一侧再
完整运行另一侧不能称为配对测量。解析按表头寻找列，不能因新增 relative/CI 列而读错 `op/s`。

## 仪器能分辨什么

- A/A 使用被测 workload 本身；分离进程的实验也用相同启动与资源拓扑验证，避免启动热状态偏差。
- 已知增量检查计时与解析是否能响应目标差异；空 harness / timer floor 用相同 batch 和完成边界测量。
- 极短 CPU loop 检查最终 codegen、防 DCE、放置与前端效应；GPU 明确事件、stream、同步和 profiler 开销。
- 并发实验记录 caller/worker 的实际落点、工作量与完成守恒；只设置宽 affinity mask 不等于逐线程固定。

无法分辨的差异报告为不确定。工具的历史字段或默认阈值只解释工具输出，不规定产品的修复门槛。

## 比值和容忍区间

建议报告中令比值大于 1 始终有利于 HYLE：吞吐使用 `Hyle/peer`，耗时使用 `peer/Hyle`。
旧脚本若方向相反，要标清并换算，不能混列。

- 区间完整高于 1 支持 HYLE 更快；完整低于 1 支持更慢；跨 1 时尚不能判断方向。
- 给定实用容忍值 `m`，双边等价带可用 `[1/(1+m), 1+m]`；等价需要区间完整落入带内，
  “没有显著差异”本身不证明等价。
- 单边非劣只回答是否排除了超过容忍值的落后，不会把稳定小幅落后变成持平。

`bench-stat.py` 的输出是给定输入与顺序下的统计结果。完整解释仍需检查数值、完成边界、A/A、顺序、
资源与真实消费者。默认运行次数和实用阈值可通过其 `--help` 查看，不要求中央注册或发布认证。

# CUDA 推理性能

更新：2026-11-01。**此前性能表作废，当前暂无通过验收的默认配置速度对照。** 旧日志仅用于排查，不作为性能结论或有效工况。

已确认的测试问题：Hyle按后续prompt的精确长度提前规划；参考按未来最大输入设置batch，且缺少默认启动warmup。此前的prefill、decode及完整进程胜负结论均撤回，不能用旧数据补新表。

下一次对照按以下边界采集：

- **冷启动：** 进程启动到真实ready，计入权重加载、编译、按配置容量准备载体／工作区、启动warmup。双方均不得使用未来请求长度或配额决定准备。
- **首次请求：** 从真实到达到首个已发布token；ready后发生的未知形状准备、初始化、提交与等待全部计入TTFT，不从局部计时中扣除。
- **后续请求：** 逐轮报告请求级prefill／TTFT和decode。只有实际先前请求建立的容量／路径才可称热路径，不能预读后续形状来制造热态。
- **完整进程与内存：** 保留启动到完成及退出的墙时；显存由独立进程测量。模型计算区间仅作诊断，不能把“主机提交到完成”当作GPU纯计算时间。

双方版本、固定容量、warmup的实际调用／行数、每轮首次形状与载体准备费用随下一张表记录；同窗交错，每臂至少3个独立进程。新结果验证后替换本页。

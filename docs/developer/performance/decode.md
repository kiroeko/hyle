# CUDA 推理性能

更新：2026-11-03，M1-9b，默认实现 `7369894f0`。**本卡验收通过。** 4K／16K／30K 的 pp512 达上游速度的 98.6%／97.6%／102.7%；整段16K／32K约持平。相对本卡起点，非零深度pp512提速5.4%～6.8%，decode保持。代价是ready增加51～78ms，GPU峰增加26～28MiB，主机私有提交峰增加126～186MiB。

## 当前默认普通推理

起点为 `6ef6d0bae`，保留了它完整的产品DLL集合。RTX4070 12GB、i9-13900K、驱动617.14；Hyle为MSVC Release、CUDA13.3.73、`HYLE_COMPONENTS=engine`、既有 `80;89-real` 配置。模型为本地Qwen3.5-2B BF16，greedy、C32768。上游固定 [b12063](https://github.com/ggml-org/llama.cpp/releases/tag/b12063)／`2cbca389f515df455412dafa07e2b1359cc72a6d` 官方Windows CUDA13.4、FA=on，沿用上游默认KV精度。

48个独立进程串行、同窗交错，每臂每场景3个；上游每进程内部5次重复不冒充独立进程。保留用户要求的GameViewer远程画面后台，无其它推理或profiler任务；逐进程GPU频率已记录。显存另用24个独立进程采样，采样进程的时间不用于下表。

默认固定512行档位在ready前预录10个模板，执行模型行数为0。计时窗口的597个完整批次均为 `capture_recorded=0, capture_reused=1`，块间后继也走捕获；3个480行尾块各首次录图一次。Batch重置仍撤销旧权限，重新绑定真实行数控制和资源后才可复用。未修改设备kernel源码；其它档位保留原有默认选择。

## 正确性与完成边界

按用户修订，以b12063原生C API、BF16 KV、C32768／FA=on为同精度teacher-forcing oracle，撤销旧HEAD分块差异的0.1失败判据。标准d=0／4K／16K／30K分别检查128／513／129／513个位置，整段16K／32736各16个位置，共1315项；1312项argmax一致。其余三项的上游top1−top2分差为0.0848465、0.0044155、0.0457878，均小于0.1。长度、epoch、RNG与真实退休检查通过。

六个相关Windows测试目标共133项通过，覆盖行数变化、无效控制、重置后复用、在途图模板的参数／状态隔离、外部Queue、共享工作区与真实退休，以及固定大查询在KV增长／缩短和换页时的数值与越界检查。本卡不扩大到MTP、启动优化或其它kernel调优。

## 普通 BF16：CPU／Vulkan／Metal

Qwen3.5-2B 原始 HF BF16，源码 `f7bd101a4`，Release，普通贪心，MTP 关闭，C256，单会话。每进程提交两次同一 105-token 提示，各生成 32 token；各路线三个独立进程。Windows CPU／Vulkan与已有 llama.cpp CPU 参考交错运行，Mac Metal单独测量；系统文件／驱动缓存保留默认状态。Windows 与 Mac 的原始权重逐字节相同，语言权重共 3589 MiB。CPU／Vulkan／Metal 的 18 个完整请求各 32 个 ID 全部一致，同窗 CPU 参考的六个请求亦一致；CUDA另以两次8-token请求复核相同前缀。

稳态取进程内第二个请求；decode 为首个输出之后的31个 token 除以其首末交付间隔。预填列是请求提交到首个输出的墙时，包含首 token 计算与交付，不能当作纯 kernel 时间。完整进程为64个输出除以进程启动到正常关闭的墙时，包含加载、首次准备和退出；Windows CPU使用当前引擎及变更模块按需重编的现有 CPU／CUDA SDK装配，其余为对应后端的静态构建。Mac最初功能预跑的首 token 为13.30s，随后三进程为1.53–1.55s；未清理系统或驱动缓存，表中首次请求不代表冷机首次安装成本。首次成本保留，不能把稳态速度当成完整短请求速度。

同窗已有上游 `b12063 / 2cbca389f` CPU参考采用同源 GGUF BF16、默认F16 KV、24线程，Hyle使用BF16 KV。上游decode中位数15.16 tok/s、预填约378ms、完整进程9.72 tok/s；上游使用HTTP内部计时，最后受控终止，Hyle使用token管道并正常关闭，两者端点不同。本节未测Vulkan／Metal上游对照，也没有重新测CUDA的三进程性能。不同硬件和请求长度的数字不能替代同设备对照；这些结果只说明当前普通BF16能力及非CUDA仍有明显的性能空间。

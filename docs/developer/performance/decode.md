准备为启动到 ready，含模型加载和启动预热；prefill 从请求到首 token，decode 含该轮首次使用开销。
输入是本轮用户 prompt；多轮 prefill 还包含上一轮待提交 token，速度按实际输入行数计算。
历史 token 是本轮之前已处理的上下文；若四个进程组不同，按普通 Hyle/参考；MTP Hyle/参考列出。
ID 是该轮自然输出对比；一旦分叉，后续轮次的实际上下文可能不同。
显存为本进程专用 GPU 内存采样峰；私有提交峰为观测到的进程私有提交操作系统峰值，不是常驻物理内存，且不包含 mmap 文件页。
GPU 采样峰是下界，跨进程共享显存不可相加；多轮的准备和内存为整次进程峰值，不是该轮增量。
每次为新进程，但不清除操作系统文件缓存；准备时间不等于首次从冷磁盘加载。
各场景的两引擎在同一窗口交错运行；不同场景及普通/MTP 使用各自窗口，不能跨窗口推算差距。

## 验收与边界

2.D已完成：普通CUDA／R1／greedy分块prefill将当前请求的token／position包一次上传，让下一块元数据准备、上一块收尾与GPU执行重叠。GPU读写仍按原队列顺序和完整completion移交；旧布局关系跨bank复用，相同前缀批量比较。MTP沿原设备接力执行并复用共同布局优化；没有新增用户开关，没有改数学kernel。

同窗对照原始基线`8749cbd12`、当前提交基线`5f5aef3db`和预热参考。16K／32K普通请求级prefill为1750.5／3805.6ms，参考1784.5／3869.7ms，速度为参考101.9%／101.7%、原始基线102.4%／103.5%。四档和两种capacity的八轮decode，最终确认数据最低为原始基线99.37%、当前提交基线99.57%，达到本卡98%门槛。

1K→32K主机准备，普通prefill为2.97→2.26ms（0.76倍）、decode为0.735→0.801ms（1.09倍）；MTP为3.04→1.59ms（0.52倍）、1.696→1.709ms（1.01倍）。MTP T2／T1分别为1.08／1.01倍，均通过1.3倍门槛；T1首次使用费用保留在完整数字内。这是C32768既定负载的有限检查，不声称所有上下文下没有布局扫描。

初验三格decode低于98%，已保留原窗口，并按预定五进程方案确认：普通1K／4K为原始基线99.83%／100.23%；32K MTP为原始基线99.88%、当前提交101.13%。128-token诊断为原始基线101.93%；Nsight中两版每步均612个kernel，未复现初验回退。不据此宣称这次小改动带来额外decode提速。

四档当前源码teacher-forcing的普通exact／packed、MTP Round／Single各16位置，argmax均与oracle一致，版本／RNG／有序发布／退休检查通过。Round与Single状态字节的差异如实报告，未新增容差；布局42项、CUDA页Source／choice21项及Model连续执行／七块prefill回归通过。1K／32K独立显存每臂3进程，36份输出完整；相对原始基线最大增加4MiB（普通）、0MiB（MTP）。未注入物理GPU故障，未做新增Apple验证。

## 复测

性能行为变化或关键节点更新完整表。逐项优化先缩小范围：例如在下方命令末尾追加 `--only long-32736-c32768 --modes off --memory-repeats 0`；未测项目会明确标为“未测”。脚本默认每臂 3 个计时进程、1 个独立内存进程；下方命令用 `--memory-repeats 3` 重测全部选定场景的显存。本表已包含 C2048／C32768 多轮；`--only multi-c32768` 可单独复测后者。

Nsight 归因先用 `python scripts/inference-nsys-prepare.py --help` 生成带边界标记的诊断源码并编译，再用 `python scripts/inference-nsys-capture.py --help` 采集对照。当前支持单轮；预热、输入、容量或首 token 边界校验失败时不生成对比表。新轨迹还分列 Hyle 主机准备与该进程 CUDA 活动、空档的重叠时间。

更新：2026-11-05。合格BF16 2B／CUDA准备目录现默认K3，产品`0b86c7d42`、冻结源码`c5db0940f`。本轮18计时＋18独立资源进程；主指标为prefill＋decode生成综合速度，不含离线转译和冷启动。默认K3为同窗b12063默认MTP的1.445倍，GPU峰多525.8MiB。24提示的策略n3窗口及最终6656位置teacher范围单独列明。此前三格式、标准／长prompt与8192质量表保留原版本与窗口，本轮未重跑这些矩阵。

## 测量口径

- RTX 4070 12GB、i9-13900K、驱动 617.14；MSVC 14.50.35717、CUDA 13.3.73，`HYLE_COMPONENTS=engine`、`80;89-real`。复用现有构建与本地 Qwen3.5-2B 权重，没有下载模型。

- 上游固定 [b12063](https://github.com/ggml-org/llama.cpp/releases/tag/b12063)／`2cbca389f515df455412dafa07e2b1359cc72a6d`，官方 Windows CUDA 13.4 包、FA=on。服务单槽、C32768、greedy、`cache_prompt`，端口 2048，启用 `--metrics`。本次未重新筛选其它上游版本或构建。

- Hyle／上游服务均为 BF16 KV。此前三格式目录中，BF16 Hyle MTP 使用原32768行子集，Q8_0／Q4_K_M MTP 使用完整草稿词表，均为K1。新版合格准备目录的自动K3单独列在首张表；上游使用自身默认MTP政策。

- Q8／Q4 指目标模型整体量化，不是 BF16 目标配独立全词表或子集量化草稿头；后者已在下方K3专用窗口单独实测，不混入默认三格式矩阵。

- 正式计时格子各3个独立新进程，各臂在对应窗口串行交错并轮换顺序；n1正确性桥接不作性能结论。保留正常桌面和 GameViewer 后台，逐进程记录 GPU 负载、频率和温度，不删除波动样本。无 profiler；每项对比使用其对应同窗数据，不与历史窗口计算代码提速。

- 八轮使用 8 个不同 prompt，每轮 64 输出；每轮第一个输出归 prefill，剩余 63 个归 decode，共 504 个 decode 输出。先按进程累加各轮 decode 墙时，再计算 `504/总秒数`，最后取进程中位数；不累加流水重叠的逐步耗时。首轮首次录图等费用保留在实际发生的请求中。

- 表中范围是 3 个独立进程的最小值–最大值；† 表示两臂范围重叠，不是显著性检验。速度比为 Hyle÷上游，越高越好；prefill／长 prompt 阶段按上游时间÷Hyle时间换算。请求 prefill 含入口／服务开销，不据此认定 GPU 吞吐优势。

- 默认三格式普通／K1 资源单独另跑 54 个进程，请求 10ms 间隔采样 PID 的 GPU 峰和 Windows 私有提交峰，实际时间戳保留在日志；本轮K3另列18个独立资源进程；采样运行的速度不参与计时结论。私有提交不是 RSS，也不能把上游 mmap 文件页算成 Hyle 的内存优势。

# CUDA 推理性能

更新：2026-11-04。推理实现 **`775de978e`，默认 Release**。GGUF Q8_0／Q4_K_M 普通模式改用 F32 层间计算，保留 BF16 KV；同窗对 HEAD 合并 decode 提升 **2.93%／3.81%**，本次共同 BF16 oracle 的 512 项数值资格均通过。MTP 默认仍为 K1，使用原精度政策。

## 测量口径

普通 decode、其驻留会话、启动与量化普通资源行使用本次新窗口：27 个计时进程（BF16／Q8／Q4 × HEAD／新版／上游 × 3）、18 个独立资源进程（Q8／Q4 × 三臂 × 3）。表中的 Hyle／上游普通模式各取新版／本次上游。MTP、标准与长 prompt、BF16 普通资源行保留 `1c73c8b47` 完整矩阵的同窗对照（原 108 进程）；它们本次没有重新测速，未拿来计算代码提速。另跑 3 个 MTP 进程确认各自512项输出不变。

- RTX 4070 12GB、i9-13900K、驱动 617.14；MSVC 14.50.35717、CUDA 13.3.73，`HYLE_COMPONENTS=engine`、`80;89-real`。复用现有构建与本地 Qwen3.5-2B 权重，没有下载模型。

- 上游固定 [b12063](https://github.com/ggml-org/llama.cpp/releases/tag/b12063)／`2cbca389f515df455412dafa07e2b1359cc72a6d`，官方 Windows CUDA 13.4 包、FA=on。服务单槽、C32768、greedy、`cache_prompt`，端口 2048，启用 `--metrics`。本次未重新筛选其它上游版本或构建。

- Hyle／上游服务均为 BF16 KV。BF16 Hyle MTP 默认使用原有 32768 行子集，Q8_0／Q4_K_M MTP 使用完整草稿词表；Hyle 默认 K1，上游使用自身默认 MTP 政策。BF16 固定 K3 另列，不替换默认。

- Q8／Q4 指目标模型整体量化，不是 BF16 目标配独立全词表量化草稿头；后者本次没有实现或测试。

- 每个计时格子至少 3 个独立新进程，双方在本轮串行交错，轮换顺序。保留正常桌面和 GameViewer 后台，逐进程记录 GPU 负载、频率和温度，不删除波动样本。无 profiler；所有对比使用本次同窗数据，不与历史窗口计算代码提速。

- 八轮使用 8 个不同 prompt，每轮 64 输出；每轮第一个输出归 prefill，剩余 63 个归 decode，共 504 个 decode 输出。先按进程累加各轮 decode 墙时，再计算 `504/总秒数`，最后取进程中位数；不累加流水重叠的逐步耗时。逐轮中位数之和不一定等于进程总和的中位数。首轮首次录图等费用保留在实际发生的请求中。

- 表中范围是 3 个独立进程的最小值–最大值；† 表示两臂范围重叠，不是显著性检验。速度比为 Hyle÷上游，越高越好；prefill／长 prompt 阶段按上游时间÷Hyle时间换算。请求 prefill 含入口／服务开销，不据此认定 GPU 吞吐优势。

- 资源独立按 10ms 间隔采样 PID 的 GPU 峰和 Windows 私有提交峰；量化普通使用本次18进程，其余资源行引用前窗39进程。实际时间戳保留在日志，采样运行的速度不参与计时结论。私有提交不是 RSS，也不能把上游 mmap 文件页算成 Hyle 的内存优势。

## 普通 decode 的带宽与精度边界

按 review 的504GB/s、每步只读一次编码权重计算理想上限。逐张量排除 NextN，目标为320张量／187个矩阵；tied embedding／完整输出头只计一次，另加选中 embedding 一行，不含文件头和填充。该口径忽略 KV、GDN、激活、写回与调度；不是实测 DRAM 利用率。权重字节核算未变，普通速度使用本次窗口。

### 精度与状态合同

- `PrecisionProfile`在冷期从完整所选角色选择GGUF Q8／Q4普通F32路径，KV/query/output另取BF16类型。量化权重与logits仍走原编码投影，没有展开整份权重。HF、其它量化reader和选中NextN的模型保留原政策。
- 层间激活、残差和conv history为F32；GDN recurrent原本就是F32。注意力Q/K/V入场转BF16，输出回F32，沿用现有FlashInfer与paged append合同。
- cache计划、hidden槽、状态池padding、前沿重采样和HostImage按实际字节计费。真实2B状态镜像的conv载荷为1,327,104字节、carry为8192字节；MTP仍为663,552／4096字节。完整导出／恢复后payload、历史包装、同形续跑、旧别名与真实退休检查通过。
- 数学和布局随存活模型固定，复用原Graph、版本、有序发布、RNG和真实退休机制。不同model/math/format身份的状态不能互换；本次未新增Graph／Compute原语、执行器或MTP政策。

本次只在Windows CUDA上验收。更广数值语料、其它平台、MTP改成F32和额外融合均未做；不把512项有限负载外推成通用质量资格。

# CUDA 推理性能

更新：2026-11-05。默认 Release，BF16 L2 修复已合入main `4dbaf5c2`，流式工具为`680d3850`；与受测实验源码`49708a8a3`／`985f3f792`逐文件一致。本轮端到端性能矩阵全部重测：**108个计时进程＋60个独立资源进程**，原main `f651afb0c`／推理`1aae1fdc1`、新版、官方b12063同窗交错，各臂n3。BF16普通／MTP领先上游 4.17%／21.82%；固定K3为K1的 94.17%，继续采用K1。普通路径另做8192位置流式数值回归。

## 测量口径

- RTX 4070 12GB、i9-13900K、驱动 617.14；MSVC 14.50.35717、CUDA 13.3.73，`HYLE_COMPONENTS=engine`、`80;89-real`。复用现有构建与本地 Qwen3.5-2B 权重，没有下载模型。

- 上游固定 [b12063](https://github.com/ggml-org/llama.cpp/releases/tag/b12063)／`2cbca389f515df455412dafa07e2b1359cc72a6d`，官方 Windows CUDA 13.4 包、FA=on。服务单槽、C32768、greedy、`cache_prompt`，端口 2048，启用 `--metrics`。本次未重新筛选其它上游版本或构建。

- Hyle／上游服务均为 BF16 KV。BF16 Hyle MTP 默认使用原有 32768 行子集，Q8_0／Q4_K_M MTP 使用完整草稿词表；Hyle 默认 K1，上游使用自身默认 MTP 政策。BF16 固定 K3 另列，不替换默认。

- Q8／Q4 指目标模型整体量化，不是 BF16 目标配独立全词表量化草稿头；后者本次没有实现或测试。

- 每个计时格子至少 3 个独立新进程，三臂在本轮串行交错，轮换顺序。保留正常桌面和 GameViewer 后台，逐进程记录 GPU 负载、频率和温度，不删除波动样本。无 profiler；所有对比使用本次同窗数据，不与历史窗口计算代码提速。

- 八轮使用 8 个不同 prompt，每轮 64 输出；每轮第一个输出归 prefill，剩余 63 个归 decode，共 504 个 decode 输出。先按进程累加各轮 decode 墙时，再计算 `504/总秒数`，最后取进程中位数；不累加流水重叠的逐步耗时。首轮首次录图等费用保留在实际发生的请求中。

- 表中范围是 3 个独立进程的最小值–最大值；† 表示两臂范围重叠，不是显著性检验。速度比为 Hyle÷上游，越高越好；prefill／长 prompt 阶段按上游时间÷Hyle时间换算。请求 prefill 含入口／服务开销，不据此认定 GPU 吞吐优势。

- 资源单独另跑 60 个进程，请求 10ms 间隔采样 PID 的 GPU 峰和 Windows 私有提交峰，实际时间戳保留在日志；采样运行的速度不参与计时结论。私有提交不是 RSS，也不能把上游 mmap 文件页算成 Hyle 的内存优势。

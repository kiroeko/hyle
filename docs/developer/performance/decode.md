- **计时：** 每臂3个独立新进程，双方在各自窗口串行交错运行，不开profiler。保留用户要求的GameViewer远程画面后台，记录GPU频率；有波动的进程仍保留。八轮用8个不同prompt，每轮64输出；首个输出归prefill，其余共504个归decode。先逐进程累加各轮不重叠的decode墙时，再取中位数，不相加流水重叠的逐步耗时。
- **冷期与资源：** 模型加载、准备、录图、启动预热归ready；ready之后首次发生的费用仍计入请求。显存／私有提交峰另开进程10ms采样，采样进程的速度不用于计时结论。私有提交不是RSS，也不把对方mmap文件页算作Hyle的内存优势。

## 正确性与采用边界

- **输出头归因门槛：** 既有K3 Nsight中，85次草稿输出头GEMM为205.639ms，草稿头总墙时273.506ms，占75.2%，超过任务卡50%门槛；K1排除末尾target-only Single后，37次草稿输出头为86.578ms。这是归因数据，不是新的吞吐跑分。
- **子集来源：** 固定24个独立提示，用本地模型普通greedy共生成6144个token、2407个不同ID。只统计生成内容，不用八轮验收的prompt或输出；未出现的ID按原ID升序补齐32768行。验收负载目标greedy输出覆盖382/512＝74.6%，逐轮为61／62／22／38／58／38／60／43个（各64）。这是有限语料子集，不是通用高覆盖词表。接受率由完整词表时的203/296降为子集180/320，收益来自更便宜的草稿，而不是接受率提高。
- **正确性：** 本卡六组普通／MTP各512个输出与同窗冻结HEAD逐项相同，三次重复、实际工作量、RNG与最终退休通过。完整BF16 oracle检查见上文，Hyle BF16为509/512一致，三处分歧均为上游margin<0.1。本卡启动改动未重复完整teacher；Q8既有KL未通过仍保留。
- **本卡测试：** 当前host-image测试源码已重编，冷Family与Phase的CPU预算拒绝／重试，以及CUDA普通packed、MTP packed、MTP分块状态、prefill接力取消／主机失败六组通过；24项对照／Nsight工具测试通过。需要后期增加T1路由或持有采样器内部输出的旧用例使用独立工作区，prefill接力使用当前共享执行工作区接口。
- **草稿头既有测试：** 7项CUDA GroupedMatMul合同检查、16个小模型词表／普通／随机用例通过。16K与32736输入的普通／MTP各一组16输出，以及K2／K3各一组八轮512输出，与同路径HEAD逐项一致；CUDA双请求和CPU回落也保持ID、工作／RNG、请求退休与既有缓存持有结果。单组检查不作性能结论。其它模型制品未配置本轮输入，不计为通过。
- **使用边界：** 有源身份绑定的准备文件才自动启用小词表；不满足采样政策时用完整词表。校准在模型准备阶段单独运行，启动按设备能力选择借用原矩阵或一次性gather，热路径设备映射ID。验证与最终输出保留完整词表。实现与准备命令见[推理指南](../../user/inference.md#草稿词表)；缩小草稿搜索空间的依据可参照[FR-Spec论文](https://arxiv.org/abs/2502.14856)。

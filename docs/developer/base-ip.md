- **目标：** 验收已实现的设备端接受和连续接力，不重写已通过的接线。CUDA、R1／N1、greedy K1 是已实现范围；其它组合必须证明合法回落。
- **验收命令：** 用 `python scripts/inference-compare.py` 按[性能表复测参数](performance/decode.md#复测)运行8个不同prompt、每轮64 token；比较当前默认接力、同源码关闭MTP后继并保留原设备Source接力的诊断控制和预热参考，同窗交错、每臂3个新进程。用 `python .scratch/inference-long-context-20261101/acceptance.py timing --capacity 32768 --lengths 1024 4096 16384 32736 --modes both` 复核长上下文；独立运行其 `memory-run` 阶段。各命令填写实际版本、控制程序和新输出目录。
- **结果：** 真实8轮相对同源码关闭后继逐轮快6.9%～13.3%，512个输出ID相同；对冻结参考第4轮范围重叠，差距未证明，两引擎输出在第1轮第57个ID首次分叉。C2048和32K显存采样峰均比同源码关闭后继多20 MiB；历史 `88e0f96b6` 的单轮总差268 MiB，冷准备不同。停止、取消、主机异常恢复、RNG及回落通过有限检查；未注入物理GPU故障。
- **用户确认的验收边界：** 显存改用同源码、相同冷准备的关闭后继组；历史总差单列。重复同一prompt原定第3～8轮不低于旧方案97%，其中第4轮两次分别为96.47%和85.7%，测量范围重叠，差距未证明；接受这一不确定性并保留设备接力。长输入每臂16 token的检查为最后退休检查前候选版，旧M1-5整体验收未因此通过。
- **不做：** 不实施2.C～2.F，不重启MTP门控或已完成的录图／启动优化。局部计时只用于归因；缺失或不公平的证据不得记为通过。

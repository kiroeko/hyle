# R6 Vulkan: source, installed static and installed shared

Product checkpoint `60de42121b1361cc9fadecc33806404ddc84a2df` passed the ordinary
public `hyle::compute` and `hyle::graph` consumer journeys on Windows RTX 4070 and
MacBook Air Mac16,12 / Apple M4 through MoltenVK. Both systems used Release/WERROR,
two build jobs and serial tests; the systems' heavy batches ran sequentially.

All three delivery forms ran the same checked numerical consumers: typed Direct
MatMul, native Recorder FFN plus custom SPIR-V, and ordinary Graph FFN plus custom
SPIR-V. The full FFN uses K67/H37/O13, M1/M16, changed inputs, repeated execution,
and an independent host oracle. Native lifecycle and failure testing is recorded
separately in the [Windows](../vulkan-r6-windows-native/README.md) and
[Air](../vulkan-r6-air-native-host/README.md) receipts; these package journeys do
not replace it.

The complete source archive was generated by the product's `hyle_source_package`
target, with source manifest commit `60de4212` and SHA-256
`2114f5381ec4f1450bb173f2a9dcea8db18b0bb6e513c375570f873e860456b2`.
That same archive was verified and consumed on both systems with
`add_subdirectory`, CPU/CUDA/Apple/oneDNN OFF, Vulkan ON, and disconnected
FetchContent using the separately supplied locked Vulkan-Headers source. It
contains the complete tracked tree, not a hand-picked verification source set.

Installed static and shared SDKs were moved to new prefixes before independent
`find_package(Hyle COMPONENTS compute/graph)` consumers configured and ran.
Both SDK forms contain the Vulkan native headers, embedded shaders and required
ggml/Vulkan-Headers license files, without the other routes' binary artifacts.
The binary consumers do not compile shaders. Windows shared HYLE DLLs are beside
each executable; their hashes are retained. On Air, the extracted producer source
and all three producer build directories were also renamed before either SDK
consumer configured. The successful consumers and recorded `otool -L` output
therefore establish independence from those original producer paths. The Vulkan
loader/driver remains a system runtime, as documented in the public guide.

Windows's initial static producer was built from the working tree that became
`60de4212`; the retained initial logs and subsequent relocation consumers cover
that SDK. Shared and complete-source journeys used the clean committed tree.
Air built every delivery from the verified complete source archive. This is a
correctness/delivery checkpoint, not an immutable P1 candidate or a route closure.
